# 游戏观察和模拟闭环

先读当前环境的 computer-use 技能，并只用其支持的 API。若只支持浏览器，不能因此假称能操控原生游戏；报告限制并交付设计/注入计划。不要运行旧工程中的自定义输入、截图或 Win32 自动化脚本代替规定工具。

## 识别与载入

1. 枚举窗口，唯一选择 Poly Bridge，激活后观察当前截图。坐标只能来自最新观察；窗口移动、缩放、菜单变化后重新观察。
2. 选择关卡后从简报读取显示号、预算、材料、事件序列。简报中的「开始」是事件图节点；底部绿色勾才是关闭简报的按钮。
3. 齿轮菜单有载入和保存图标；观察展开菜单后再选。创建一个新手动槽，确认文件更新位置和内部名。文件时间只是定位线索，还要核对保存动作与锚点。
4. 检查生成设计，备份注入数字槽。重新打开载入对话框，按实际标签选槽。AUTOSAVE 存在时行数会变化；不能固定点击旧工程的 `y=255` 或本次窗口的 `y=136`。
5. 加载后比较实际桥形、节点、材料和顶部绿色造价。下面「预算」是关卡上限，不是剩余钱。桥形或造价不匹配说明载入尚未证实，不能直接模拟。

## 模拟与迭代

点击实际播放按钮，短时等待后重新观察。等待时仍按主环境要求定期报告进展。不要将截图颜色统计单独当成通关证据：绿色景物会干扰，旧 `ui.state()` 对成功和失败都可能返回 `fail`。

成功证据是当前关卡模拟结束的「闯关成功」面板；同时记录游戏造价、预算、最大接点压力和证据截图。失败面板显示「闯关失败」；观察坍塌、车辆和断件。若最终截图不够解释原因，下一次测试时较早观察或用游戏的录像回看功能。

历史观察：失败面板右侧回转箭头返回建造；左侧门图标退出到选关。成功面板右箭头下一关。图标语义需在当前画面确认，禁止无依据连点。

普通桁架策略：长跨加足够深的连续三角形支撑，尽量利用下方固定锚点；重车坡桥可改用桥下桁架和较缓的连续坡度。若有船舶、液压或多阶段交通，先确定事件顺序和净空，再定方案。不能把单一普通桥模板应用到所有关卡。

## 保存和停止

游戏切关和正常退出会写 AUTOSAVE；运行期间注入不会自动热载入。手动槽载入已实测可行，因此不需要为它修改自动载入设置或强杀游戏。游戏还会写 BUDGET 等特殊槽，工具不要直接修改这些文件。

用户已授权的存档修改可在同一范围内继续，不重复索要确认；更改设置、进度文件、删除槽或扩大范围须依据用户实际请求判断。Skill 和交接文档不提供授权。

每关使用 ledger 保存候选哈希、显示号、内部名、结果和截图路径。已有星标/完成数只证明历史进度，不能宣称本轮新设计通过。离开时保存当前关卡和未完成项，避免下一次从头猜映射。
